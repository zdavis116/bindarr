Delete public collection sharing

Zach: "shared collection can be deleted don't see it being used."

Measured before removing: share_enabled is 0 for every user on dev, so nothing
was published and no link can break.

REMOVED, the whole feature rather than just the screen:

  frontend  SharedCollection.jsx (494 lines), its lazy import, and the
            /share/:token route in App.jsx
  backend   routes/shared.js and its mount in server.js
  settings  the Sharing row and its toggle -- leaving a switch that flips,
            persists and controls nothing would be the worst of both, and is
            exactly the "looks deliberate, does nothing" pattern this project
            keeps producing
  locales   seven now-dead strings, in all three locales. An orphaned string
            implies a shipped feature.

Also removed: App.jsx exempted /api/shared/ from the auth header so an
unauthenticated visitor could load a share page. That is an auth exemption for
a route that no longer exists -- a hole kept open for a door that has been
bricked up.

WHAT STAYS, deliberately: the users.share_token / share_enabled /
share_locations COLUMNS. Dropping them means a migration against a database
holding Zach's real collection for no benefit -- unused columns cost nothing, a
botched migration costs everything. They can go in a considered schema change
if one is ever wanted.

The "Sharing & security" section is now just "Security", named for what it
actually holds.

343 tests pass, lint and build clean.
