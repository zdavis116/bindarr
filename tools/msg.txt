Build the deck view to the approved mockup

DeckView.jsx replaces 1,056 lines inside DeckBuilder.jsx. Zach reviewed the
mockup (sketches/009-deck-view) line by line and approved it, so the mock was
the spec here rather than the inspiration -- the mistake that cost three rounds
of rework on Collection and the deck list.

KEPT at his direction after I listed what the rebuild would drop: quantity
editing, commander swap, and moving cards between the deck and Considering.
DROPPED, agreed: checkout / in-play, the printing picker, card categories,
playtest.

FOUR BUGS CAUGHT BEFORE SHIPPING, all by asking the real API instead of
assuming:

  1. COST TO FINISH WOULD HAVE BEEN ZERO ON EVERY DECK. The deck query joins
     card_cache but never selected a price. Fixed server-side in
     deckIdentity.js so the figure comes from the database, not a client guess
     -- the same trap that had the multi-deck buylist reading $0.00 for two
     rounds.

  2. THE EXPORT CHIPS WERE FICTION. The mock drew five: Plain, Moxfield,
     Archidekt, TCGplayer, Manapool. buildDeckExport supports three things --
     buylist, mtga, and plain -- differing by bracket style. Four of those five
     chips would have emitted identical text, which is worse than three honest
     ones: an export that looks richer than it is hands over the wrong format
     silently. Now Moxfield, Manapool and Names only, named for where they are
     pasted.

  3. WARNINGS WOULD HAVE RENDERED BLANK. They arrive as { code, message }; I
     read .text. A column of empty, alarming rows. MISSING_COPIES is also
     filtered out -- the Missing tab and the cost already say it, and Zach cut
     the equivalent "short of 100" warning for exactly that reason.

  4. THE COMMANDER-SWAP CONFIRMATION WOULD NEVER HAVE APPEARED. The error
     handler SPREADS details at the top level of the body; I read
     body.details.removing. The swap would have surfaced as a bare error toast,
     losing the named list of cards it wanted to remove -- which is the whole
     point of the refusal.

Also: POST /api/decks/:id/cards takes flat fields, not { cards: [...] }, so
every add would have been a 400 with the search appearing to work.

deckView.test.js pins eight properties. Five were verified by REINTRODUCING the
bug and watching the case fail: sections read from the colours column,
considering counted in the deck, the invented price field, quantity sent as a
delta, and the 409 treated as a plain error.

The old detail-view handlers are now unreferenced but NOT deleted. An automated
sweep of them cut into neighbouring code and produced four syntax errors; dead
code is recoverable where deleted capability is not, and handleDeleteDeck was
nearly lost that way earlier this week. They come out in a separate verified
pass, with an eslint-disable banner and a note at the render site so the build
stays honest in the meantime.

378 tests pass; lint and build clean.
