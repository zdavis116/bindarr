Remove the dead detail-view code and drop the eslint-disable

DeckBuilder.jsx: 2,209 -> 1,459 lines. 772 deletions, 21 insertions.

When DeckView.jsx replaced the old 1,056-line detail view, ~40 handlers, state
pairs and chart builders were orphaned. An automated sweep of them produced
four syntax errors by brace-matching into neighbouring code, so they were
parked behind `/* eslint-disable no-unused-vars */` with a note, rather than
deleted in a hurry. This removes them properly and takes the banner off.

METHOD: one declaration at a time, rebuilding after each, reverting the single
edit that breaks the build rather than the file. A bad match then costs one
function instead of an afternoon.

THE BANNER WAS HIDING REAL BUGS, which is the argument for removing it rather
than leaving it parked. With no-unused-vars off, no-undef was also suppressed,
and two live symbols turned out to be broken by earlier passes:

  * TONE_STYLES looked dead because StatusBadge and PrintingBadge -- its only
    obvious users -- were dead. A LIVE import-preview panel still uses it.
  * searchResults / buylistLoading were removed while runResultsSource,
    refreshResultsPanel and refreshBuylist still wrote to them. Those three are
    reachable from loadDeckDetails, which DeckView calls through onChanged
    after every edit.

Both surfaced only once the rule was back on.

The second one was fixed by removing the WRITES, not by restoring the state:
the panels that read those values became DeckView, so a setState with no reader
was re-rendering a 1,500-line component on every deck refresh for nothing.

KEPT DELIBERATELY: loadDeckDetails and the three refresh functions beneath it
are live, not dead. buylistBracketStyle became a plain const -- nothing writes
it any more, so calling it state overstated what it does.

343 tests pass, 0 fail. Lint clean with no suppressions. Build clean.
